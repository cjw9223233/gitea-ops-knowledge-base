## 先看全貌

{{diagram:architecture}}

!!! tip "白話說明"
    **Gitea** 是公司放程式碼的網站，跑在一台 Linux 主機的 **Docker** 容器裡；它把資料存在旁邊的 **PostgreSQL** 資料庫與檔案目錄。**備機**是另一台機器，每天晚上收一份備份檔，但它**還不會自動接手服務**。你要做的第一件事不是改設定，而是學會「安全地看」。

## 三個位置、兩種身分

| 名稱 | 位置 | 用途 |
|---|---|---|
| 正式主機 | `coffee@10.253.114.160` | 運行 Docker、Gitea 與 PostgreSQL |
| 備機 | `coffee@192.168.1.3` | 接收備份封存檔，尚非已驗收的即時接手服務 |
| 本機工作站 | Windows 專案資料夾 | 編輯知識庫與保留報告，不執行 Linux 主機命令 |

主機與備機的登入帳號**都叫 `coffee`**，不能只看提示字元判斷自己在哪台機器；先執行 `hostname` 確認。`sudo crontab -l` 查的是 **root 排程**：root 負責冷備份與服務控制，新版只讓 SSH 以 **coffee** 身分連備機。

## 操作分級

網站上每個指令區塊左上角都有標籤，代表風險等級：

| 標籤 | 意思 | 原則 |
|---|---|---|
| 唯讀 | 只讀取狀態，不改變任何東西 | 可以先蒐集證據；輸出不要包含密碼或私鑰 |
| 變更 | 會修改設定、檔案或權限 | 先確認版本、回復方式與管理員權限，並留下紀錄 |
| 中斷服務 | 會停止 Gitea、重開機或覆蓋資料 | 只在核准的維護時段、正確目標上執行；必須有前置、回退與驗收 |

!!! warning "新手不要做這些事"
    1. **不要**對 `/home/Gitea` 執行 `chmod -R` 或 `chown -R`：PostgreSQL 與 Gitea 的容器使用者不同，整棵改權限會讓資料庫起不來。
    2. **不要**在上班時段手動執行 daily 備份：它會讓 Gitea 停機約 3 分鐘。
    3. **不要**刪除鎖檔或 `recovery-required.json` 來「讓排程跑起來」：先確認服務狀態與日誌。
    4. **不要**刪除 `.partial` 資料夾：它可能是唯一一份未完成的證據，先查日誌。
    5. **不要**把完整的 `docker inspect` 或 `docker compose config` 輸出貼進工單：裡面可能有資料庫密碼。
    6. **不要**關閉 Docker 的防火牆管理，也不要直接執行舊的 `gitea-access-rules.sh`。
    7. **不要**因為「ping 得到」就認為服務正常：要用 `healthz` 與實際 clone 驗證。

!!! info "給維運：貼指令的習慣"
    每次只複製一個程式碼區塊。若一行用 `&&` 串接，前一步失敗就會停止。多行指令不要黏成一行。提示字元相同（`coffee@…`）時，先 `hostname` 再執行。

## 遇到問題找誰

角色負責人姓名尚待 PM 填寫（見 [權限與帳號](access.html) 的角色表）。在名單補齊之前，先依下表判斷要找哪一類人：

| 問題類型 | 先找 |
|---|---|
| 連不上網站、Git 或 SSH | 網管 |
| 備份、排程、主機、Docker | Linux 管理員 |
| 帳號、組織、專案權限 | Gitea 管理員 |
| 進度、風險、驗收、是否要停機 | PM |
