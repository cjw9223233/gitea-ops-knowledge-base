這頁把網站裡會看到的術語，用白話解釋，並說明在這個系統裡長什麼樣子。標示「新手必讀」的詞，Day 1 先讀。

## 備份與還原

| 名詞 | 白話 | 在這個系統裡 |
|---|---|---|
| 冷備份（新手必讀） | 先把服務停下來再備份，資料不會在複製到一半時被改動 | 每個平日 20:30 先停 Gitea 與資料庫約 3 分鐘，再打包；備份檔是 `gitea-cold.tar.gz` |
| 熱備份 | 服務運行中直接複製，可能得到不一致的資料 | 舊流程用 `scp` 直接複製資料庫目錄，已停用 |
| RPO（新手必讀） | 最多能接受遺失多久的資料 | 平日一天一份，所以最壞可能損失將近一天；週末沒有新的 daily，可能更久 |
| RTO（新手必讀） | 出事後最多能接受多久恢復服務 | **尚未實測**，要靠還原演練才知道 |
| 異機備份 | 把備份放到另一台機器，避免同一台壞掉就全沒 | 備機 `192.168.1.3` 的 `/home/coffee/gitea-backups/` |
| checksum／SHA-256 | 檔案的指紋，內容改變指紋就不同 | `SHA256SUMS` 檔；備機收完會核對才發布 |
| `.partial` | 還沒完成的資料夾 | 傳輸或製作中、或中途失敗；先查日誌，不要直接刪 |
| `SUCCESS`／`REMOTE_SUCCESS` | 兩個成功標記檔 | 前者＝本機備份完成；後者＝已通過備機校驗。兩者都**不等於**還原成功 |
| 還原演練 | 真的拿備份在隔離環境把系統重建一次 | 尚未進行；見 還原與演練 |
| 3-2-1 原則 | 3 份資料、2 種媒介、1 份在異地 | 目前未達成：同一顆 SSD、未異地、weekly 未外送 |

## 網路與時間

| 名詞 | 白話 | 在這個系統裡 |
|---|---|---|
| 埠（port）（新手必讀） | 一台機器上不同服務的「門牌號碼」 | 3000＝網站、2222＝Git SSH、22＝維運 SSH |
| 白名單 | 只讓名單上的來源連進來 | 由防火牆規則實作，新增使用者要先申請來源 IP |
| NAT | 讓內部機器共用一個出口位址上網 | 主機可能替 `192.168.1.0/24` 做 NAT（腳本在，生效待確認） |
| NTP／校時（新手必讀） | 讓電腦時鐘跟標準時間對齊 | 目前全部來源連不上，時鐘比標準時間快約 50 分鐘 |
| `Leap status: Normal` | chrony 自我檢查的一個欄位 | **不代表已校時**；目前是自己跟自己比。要看 `Reference ID`、`Stratum` 與 `^*` 來源 |
| WoL（Wake-on-LAN） | 網路上送一個特殊封包就能叫醒關機的電腦 | `eno1` 已開啟，是 22:00 後被喚醒的可疑來源之一 |
| RTC／BIOS 鬧鐘 | 主機板上的小時鐘，可在設定時間叫醒電腦 | 設計上 07:00 叫醒；目前被其他喚醒搶先 |
| 同網卡雙 IP | 一張網卡設兩個位址 | `10.253.114.160` 與 `192.168.1.2` 都在 `eno1`，不是兩條獨立線路 |

## 系統與權限

| 名詞 | 白話 | 在這個系統裡 |
|---|---|---|
| root | Linux 的最高權限帳號 | 執行維護排程；SSH 目前仍允許 root 登入（待收斂） |
| sudo | 暫時借用 root 權限執行單一指令 | `coffee` 屬於 `sudo` 群組 |
| docker 群組（新手必讀） | 能操作 Docker 的使用者群組 | **等同 root 等級**，不能給一般開發者 |
| UID／GID | 系統用數字記錄「誰」 | Gitea 容器 1000:1000；PostgreSQL 999；主機上顯示的名字可能不同，不代表資料屬於那個服務 |
| 遞迴 chmod／chown | 一次改整棵目錄的權限／擁有者 | 在 `/home/Gitea` 上**禁止**，會破壞資料庫 |
| SSH 金鑰 | 用一對檔案代替密碼登入；公鑰放伺服器、私鑰自己保管 | 私鑰永遠不貼進文件或聊天；見 [權限與帳號](access.html) 的金鑰清冊 |
| 共用帳號 | 多人使用同一個登入帳號 | 主機只有 `coffee`，無法分辨是誰操作 |

## Docker 與 Gitea

| 名詞 | 白話 | 在這個系統裡 |
|---|---|---|
| 容器 | 把程式和它需要的環境包在一起執行 | `gitea-server-1` 與 `gitea-db-1` |
| Compose | 用一個設定檔描述多個容器 | `/home/Gitea/docker-compose.yml`，專案名 `gitea` |
| `restart: always` | 容器掛掉或主機重開後自動重啟 | 兩個 Gitea 容器都設定了 |
| healthz（新手必讀） | Gitea 提供的健康檢查網址 | `http://127.0.0.1:3000/api/healthz`，預期 `status: pass` |
| `Up` 不等於健康 | 容器行程活著，不代表網站與資料庫可用 | 要另外測 healthz 與 clone |
| `DOCKER-USER` | Docker 留給管理員放防火牆規則的位置 | 白名單腳本寫在這裡 |
| rootless 映像 | 容器內的 Gitea 用非 root 使用者跑 | 不代表整個 Docker daemon 是 rootless |

## 排程與日誌

| 名詞 | 白話 | 在這個系統裡 |
|---|---|---|
| cron（新手必讀） | Linux 的排程器，依時間自動執行指令 | root crontab 有三項工作 |
| anacron | 補跑錯過的例行工作 | 只管系統預設工作；**不會**補跑備份 |
| logrotate | 定期把日誌換檔、壓縮、清舊 | 每天 00:00 輪替，所以午夜後的 `daily.log` 是空的，看 `.log.1` |
| 維護鎖 | 防止兩個維護工作同時跑 | `/run/lock/gitea-maintenance.lock` |
| 復原標記 | 備份中途失敗時留下的警示檔 | 存在時新備份與關機會被擋；先確認服務再處理 |
| journal／syslog | Linux 的系統日誌 | `journalctl` 可查前幾次開機；syslog 目前被 snap 重啟迴圈洗版 |
| UTC | 世界標準時間，台灣時間減 8 小時 | 備份資料夾名稱用 UTC，`…T123003Z` ＝台灣 20:30 |
