## 已有證據

- 使用者觀察：BIOS 一開始看不到硬碟，重開或斷電後才出現。
- 系統碟為 ata1.00 → /dev/sda，512GB SATA Flash Drive、韌體 SFDM104B；成功開機時建立 6.0 Gbps 連線。
- SMART PASSED、No Errors Logged、CRC／ICRC 計數為 0；無自我測試紀錄。
- 型號不在 smartctl 資料庫，多個廠商欄位未知；不能把 231 的 98 解釋成剩餘壽命 98%。
- COMRESET 1780 不等於 1780 次故障；需要增量與事件對照。
- BIOS 為 2012 年 AMI 4.6.5；ChiefRiver／OEM 欄位不足以選擇可刷入的更新檔。

成功開機紀錄不能排除間歇性異常。先前 failed to resume link 出現在其他通道，不能直接當成系統 SSD 已壞的證據。

## 處理優先序

| 優先度 | 可能原因／任務 | 確認與解法 |
|---|---|---|
| P0 | 資料保全 | 完成可讀取的異機一致性備份，再安排重開與拆機 |
| P1 | 接頭、排線、轉接板 | 完全關機斷電後檢查；一次替換一項 |
| P1 | SSD 控制器或初始化 | 正常 SSD 在原主機、原 SSD 在正常環境交叉測試 |
| P1 | 供電不穩 | 使用符合規格的正常電源測試，分開記錄冷開機與暖重啟 |
| P2 | 主機板／BIOS | 其他元件排除後查原廠適用修正，不能刷通用 AMI 韌體 |
| P3 | 開機順序／CMOS | 只有斷電後日期或設定重設才提高優先度；不要先重灌 GRUB |

## 10/5 關機行為補查

近日日誌顯示 22:00 到達 poweroff 流程後，約十幾秒即出現新的 boot。尚未證明與 SSD 故障為同一原因；需有人值守核對 BIOS RTC、WOL、電源恢復與外部喚醒。不要為測試而遠端反覆強制重開。

## 唯讀健康檢查

```bash-ro
sudo smartctl -x /dev/sda
```

貼回檢查輸出時可遮蔽序號，保留型號、韌體及錯誤欄位。主機已於 9/23 安裝 smartmontools，不需為每次檢查重新安裝。
